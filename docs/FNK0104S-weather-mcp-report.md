# FNK0104S — Weather и XiaoZhi MCP

## Реализация

WeatherService продолжает использовать Open-Meteo Forecast API для получения погоды по
координатам. Для поиска населённых пунктов используется официальный Open-Meteo Geocoding API
(`geocoding-api.open-meteo.com/v1/search`). Геокодирование не заменяет погодный API: оно только
возвращает проверенные координаты и идентификаторы кандидатов.

Добавлены четыре MCP-инструмента:

- `self.weather.search_city` — поиск до пяти кандидатов с `candidate_id`, названием, страной,
  регионом, часовым поясом и координатами;
- `self.weather.get_city` — чтение постоянного города Weather;
- `self.weather.set_city` — смена города только по свежему `candidate_id` из поиска;
- `self.weather.get_weather` — разовый запрос текущей погоды и прогноза для кандидата или
  сохранённого города.

Кандидаты хранятся только временно, имеют срок действия десять минут и заменяются новым
результатом поиска. Координаты от LLM напрямую не принимаются.

## Постоянная настройка

Выбранное местоположение сохраняется в NVS namespace `weather`: широта, долгота, название,
страна, код страны, регион, часовой пояс и идентификатор провайдера. SD-карта для этого не
нужна. При пустом или повреждённом NVS используется исходный город по умолчанию — Гданьск.
Повторный выбор того же города не выполняет повторную запись.

Разовый `get_weather` не меняет город, Weather UI или постоянный cache. `set_city` сбрасывает
старый cache, обновляет подпись на экране и ставит обычное обновление Weather в очередь.
Ответы MCP содержат структурированные JSON-поля и явные ошибки (`network_unavailable`,
`time_not_synced`, `candidate_not_found`, `candidate_expired`, `nvs_save_failed` и т.д.).

## Асинхронность и память

В WeatherService создан один долгоживущий worker с ограниченной очередью запросов. Поиск и
разовые запросы не выполняют HTTP/TLS в LVGL callback, аудиозадаче или основном обработчике
MCP. Одновременно выполняется только один погодный запрос; HTTP timeout — 10 секунд,
ответ ограничен 64 KiB, временные JSON-буферы освобождаются после разбора. Ответ MCP
отправляется после завершения worker через безопасное планирование в Application.

Если город меняется во время запроса, результат старого запроса отбрасывается и не может
перезаписать данные нового города. Persistent cache остаётся атомарным и помечается stale,
если сеть или API недоступны. В ответ не добавляются отсутствующие у API поля.

## Изменённые файлы

- `main/weather/weather_service.h/.cc` — единая модель местоположения, NVS, геокодирование,
  разовые запросы, MCP и постоянный worker;
- `main/mcp_server.h/.cc` — асинхронные MCP-инструменты;
- `main/settings.h/.cc` — безопасные `TrySetString`, `Commit` и отмена незакоммиченных изменений;
- `main/boards/freenove-fnk0104s/freenove_fnk0104s_board.cc` — регистрация Weather MCP;
- `main/display/lcd_display.cc` — отображение сохранённого города и обновление после `set_city`.

## Проверка

Сборка выполнена для `freenove-fnk0104s` с ESP-IDF 6.1.0:

- `idf.py build` — успешно;
- `build/xiaozhi.bin` — создан;
- размер приложения `0x3DD330`, свободно в минимальном app-разделе `0xA2CD0` (14%).

На реальном устройстве отдельно нужно проверить поиск городов на русском, польском и английском,
неоднозначные города, смену города во время запроса, перезагрузку/OTA с сохранённым NVS,
пустой NVS, отсутствие сети, отсутствие SD и одновременное воспроизведение музыки.

После отчётной проверки версия 1.1.13 собирается и прошивается отдельным релизным шагом.
